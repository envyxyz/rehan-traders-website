## Root cause of "chat and email don't work"

The Vercel test deploy serves only the static export. `/api/book`, `/api/chat`, `/api/estimate` and `/api/upload` live in the Cloudflare Worker (`worker/`), which Vercel never runs, so every call 404s: the booking falls back to the `WEB-` WhatsApp reference (the screenshot), the chat shows its fixed reply. The Worker, the AI providers, the Apps Script and the shop email all work when the Worker runs.

## Findings

### Blockers (features broken)

- **B1. No API on Vercel.** Add thin Vercel Edge functions in `api/` that call the Worker's handlers, and a `vercel.json` (static output `out/`, clean URLs). Cloudflare stays the production host. Needs the seven env vars in the Vercel project.
- **B2. Booking sheet device picker.** The brand list renders in the page flow, so opening it pushes the Model field down by up to 288px, and the sheet scrolls inside a scrolling list (double scroll). It must overlay the field below, flip up when there is no room, and never make the sheet scroll. Lighthouse also flags `aria-valid-attr-value` on both inputs (cmdk's `aria-controls` points at a list that isn't mounted).
- **B3. Booking sheet scrolls.** At 390×664 the sheet scrolls (724/648px) even with the list closed. Every step should fit at 1440×786 and 390×664.
- **B4. Chat unreachable on phones at load.** The launcher is `max-md:hidden`; the only phone entry is an icon inside the sticky bar, which appears only after scrolling 80% of a screen. Should be an icon button on phones, always there.
- **B5. Photo upload can forge bookings.** `/api/upload` splices the client's raw JSON after the Worker's own `"action":"upload"`; JSON's last duplicate key wins, so a client can send `"action":"book"` with any fields and the Apps Script saves a booking and emails the shop with no validation, honeypot, timing or slot check, and a `whatsapp` link of the attacker's choosing.
- **B6. Booking e2e tests broken.** Faults are now `TogglePill` buttons, the specs still look for radios.
- **B7. Home "Not sure what's wrong?" box regressed.** The pre-Phase-6 WIP (restored from the stash) points it back at WhatsApp; Phase 6 shipped it to `/estimate?q=`.
- **B8. Chat locks up after closing mid-reply.** Closing the sheet while a reply streams saves an empty assistant message; every later request fails Zod (`min(1)`) and the panel shows the fixed reply until a reload.

### High

- **H1. Home loads Google Maps on first load.** The home Visit section has a live iframe; Chrome's lazy threshold still loads it on mobile, ~600 KB of Maps JS (main.js, places.js, util.js…). `InteractiveMap` (tap to load) already exists on `/visit`; reuse it. Also breaks PRD §8 (no map on home).
- **H2. Horizontal overflow.** Every page at 320px (a button reaches 371px), `/reviews` at 320 and 390 (`div.sm:ml-auto` to 422px), `/visit` at 320 and 390 (button to 407px).
- **H3. Home TBT 790 ms, LCP 5.7 s** (h1 render delay 2.7 s). The shared chunk takes ~960 ms of scripting. Also `/estimate` TBT 690 ms, `/about` 600 ms.
- **H4. Confirmation page.** Downloads the ticket PNG automatically on load (no gesture). "Save ticket" calls `navigator.share` after `await ticketImage()`, so iOS drops the gesture and the error is swallowed: nothing happens.
- **H5. Booking rejects normal text.** The Worker's `problem` regex refuses a leading `-`/`+`/`=`/`@` and any `<`/`>` ("- battery <20%"), with only a generic error. The Apps Script already neutralises formulas (`cell()`) and escapes HTML (`esc()`).
- **H6. Invented claims in copy** (rule 10): privacy page says chat messages "are not used to train public models" and calls the providers "privacy-respecting" (AI Studio free tier may train on prompts); About calls Adnan "Founder and technician" (unconfirmed); reviews are called "verified"; the `/reviews` meta description hard-codes "4.9 from 50" instead of using `reviews.rating` / `reviews.count`.
- **H7. Apps Script source drifted.** The deployed script (`code + appsscript.txt`) uses `MailApp`, returns `emailSent`/`emailError` and has `testEmailAndDrive()`; the repo's `Code.gs` doesn't. `recentForPhone` stops at the first old row, so sorting the sheet breaks the 5-per-hour limit.
- **H8. Uncommitted work.** 18 modified and 20 new files (Phase 7 pages, photo upload, ticket image, map facade, Apps Script photos) are not in git. The stash `wip-before-phase6-pull-1030` is fully contained in the working tree. The `phase-6` worktree is clean and merged.

### Medium

- **M1. Accessibility (Lighthouse):** `heading-order` on `/repairs` (card h3 with no h2) and `/faq` (accordion h3); `color-contrast` on `/reviews` (`text-steel-soft` captions); `label-content-name-mismatch` on WhatsApp buttons (aria-label "Chat on WhatsApp, 0305…" doesn't start with the visible "WhatsApp").
- **M2. Static-export prefetch 404s.** The client asks for `/__next.!KHNpdGUp.__PAGE__.txt`, the build writes `out/__next.!KHNpdGUp/__PAGE__.txt` (`!KHNpdGUp` is the `(site)` route group). Console errors on every page (Best Practices 96) and failed prefetches on any static host.
- **M3. Dead weight in every page:** `<Toaster>` (sonner) and `<TooltipProvider>` in the root layout serve only `/dev/kitchen-sink`.
- **M4. Over-engineering / dead code:** unused `cn` npm package; unused `ui/select.tsx`; unused `devices` export in `content.ts`; `home.tsx` re-implements `ServiceCard` instead of using `service-card.tsx`; `shadcn` (CLI) in runtime dependencies.
- **M5. Booking day tiles at 320–360px:** seven `flex-1` tiles in ~288px are ~37px wide, under the 44px target.
- **M6. SEO gaps:** `/estimate` missing from `sitemap.ts`; check home canonical/OG and PRD §8 JSON-LD (home `MobilePhoneStore`, repair `Service`/`FAQPage`).
- **M7. Photo picker** never revokes its object URLs; drops can read a stale `photos.length`.
- **M8. `OpenStatus` fallback** hard-codes "10 PM" instead of reading `site.hours`.

### Low

- `adjustFontFallback: false` doesn't silence the "Failed to find font override values for Google Sans Flex" warning (it shows in every build either way); revert to the one-liner.
- `loading.tsx` spinner may add a second red element per view; check rule 5 on `/visit` too.

## Dev server spam and CPU

- Wrangler's interactive session (hotkey bar, cursor escape codes) redraws through `pnpm --parallel`'s prefixed output on Windows. Fix: `--show-interactive-dev-session=false`.
- Wrangler's debug logs hold thousands of `Runtime.getIsolateId` inspector round-trips per session: a DevTools client (VS Code auto-attach or Chrome's target discovery) polling the Worker's inspector.
- Next's `/api` rewrite targets `localhost:8787`; on Windows `localhost` tries `::1` first while wrangler listens on `127.0.0.1`. Use `127.0.0.1`.
- Orphans: stopping `pnpm dev` with Ctrl+C on Windows can leave `next`, `wrangler` and `workerd` running. At audit time a previous `pnpm dev` tree and static servers on 3100, 3101 and 4100 were still running.
